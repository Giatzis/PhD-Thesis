# Section 7: DCR Process Graph Generation

## What is a DCR Graph?

A **Dynamic Condition Response (DCR) Graph** is a formal process modeling notation used to represent behavioral constraints between events. In the context of this analyzer, DCR graphs serve to formalize the behavioral lifecycle of each detected design pattern.

For example, the Access Control pattern has events like "Grant Capability," "Execute Protected Function," and "Revoke Capability" — and DCR relations define their ordering and constraints (e.g., "Execute can only happen if Grant has already occurred").

DCR graphs in this system are generated by the `DCRGraphGenerator` companion module (imported at the top of the file). The analyzer's role is to **dispatch** graph generation to the appropriate generator method based on which patterns were detected.

It is important to note that this conversion is performed using hardcoded code that generates the theoretical, high-level graph of the architectural pattern in question. It does not dynamically extract the control flow from the specific code being analyzed. Instead, it functions as a theoretical model, generally associating objects (such as an AdminCap or an UpgradeCap) with the expected events that govern their lifecycle, based on sound architectural design.

---

## `_generate_dcr_graphs()`

```python
def _generate_dcr_graphs(self, patterns: Dict, module_name: str) -> List[Dict]:
    """Generate DCR graphs"""
    graphs = []

    if PatternTypes.ACCESS_CONTROL in patterns:
        try:
            process = self.dcr_generator.generate_access_control_graph(
                module_name=module_name,
                capability_struct="AdminCap",
                functions={"grant": "new", "protected": "protected_call", "revoke": "destroy"}
            )
            graphs.append(process.to_dict())
        except Exception as e:
            print(f" ⚠️ Could not generate Access Control graph: {e}")

    if PatternTypes.CIRCUIT_BREAKER in patterns:
        try:
            process = self.dcr_generator.generate_circuit_breaker_graph(
                module_name=module_name,
                deny_cap_struct="DenyCap",
                functions={"pause": "pause", "unpause": "unpause", "operation": "execute"}
            )
            graphs.append(process.to_dict())
        except Exception as e:
            print(f" ⚠️ Could not generate Circuit Breaker graph: {e}")

    if PatternTypes.TIME_INCENTIVIZATION in patterns:
        try:
            process = self.dcr_generator.generate_time_incentivization_graph(
                module_name=module_name,
                wallet_struct="Wallet",
                functions={"start": "new", "proceed": "claim", "timeout": "complete"}
            )
            graphs.append(process.to_dict())
        except Exception as e:
            print(f" ⚠️ Could not generate Time Incentivization graph: {e}")

    if PatternTypes.ESCAPABILITY in patterns:
        try:
            process = self.dcr_generator.generate_escapability_graph(
                module_name=module_name,
                upgrade_cap_struct="UpgradeCap",
                functions={"authorize": "authorize_upgrade", "escape": "commit_upgrade", "immutable": "make_immutable"}
            )
            graphs.append(process.to_dict())
        except Exception as e:
            print(f" ⚠️ Could not generate Escapability graph: {e}")

    return graphs
```

Each generator call uses `try/except` so that a failure in DCR generation (e.g., if the companion module is unavailable) does not abort the entire analysis. The graph is serialized via `.to_dict()` before being returned, converting the internal `DCRProcess` object into a plain Python dictionary suitable for JSON export.

---

## Parameters Passed to Each Generator

| Pattern | Struct Hint | Function Roles |
|---------|-------------|----------------|
| Access Control | `AdminCap` | `grant`, `protected`, `revoke` |
| Circuit Breaker | `DenyCap` | `pause`, `unpause`, `operation` |
| Time Incentivization | `Wallet` | `start`, `proceed`, `timeout` |
| Escapability | `UpgradeCap` | `authorize`, `escape`, `immutable` |

These parameters are **hints** passed to the DCR generator so it can label the graph nodes with meaningful names. The actual behavioral logic of the DCR model is determined inside `DCRGraphGenerator`.

---

## Where DCR Graphs Appear in the Output

The returned `graphs` list is included in the final result dictionary under the key `"dcr_graphs"`. The UI can then render these as visual process diagrams. In the JSON export, each graph is a structured dictionary containing events, relations, and metadata.
